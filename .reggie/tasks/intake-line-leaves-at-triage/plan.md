# Remove the intake line at triage instead of at plan done, and report a scaffolded but unfilled brief as ungroomed

## Problem
`.reggie/intake.md` promises, in its own header, to hold raw items waiting for triage, and then promises in the next sentence that a line survives until its plan is merged. The code follows the second sentence: `removeFromIntake` in `capture.ts` has exactly one caller, `reggie plan done` in `cli.ts`, a verb a person has to remember to type after the plan is written. So the file is a log of everything ever captured rather than the queue of unshaped work, and the reader has to remember which lines were already answered by a brief.

That is not hypothetical here tonight. Measured against this repo, `reggie tasks --json --all` reports 70 tasks, 17 of which have a brief on disk, and 12 of those 17 still carry an intake line: the six groomed items (`branch-diff-in-reader`, `derive-the-journal`, `idea-from-every-page`, `intake-line-leaves-at-triage`, `low-risk-auto-approval`, `needs-you-queue`) and six of the eleven done ones (`a-task-worktree-has-no-node-modules-so-nothing-r`, `docs-check-in-ci`, `false-tests-sentence`, `graph-coverage-published`, `note-form-on-repo-and-area`, `task-attribution-by-merge`). The other five done tasks had `plan done` run by hand. Of 65 intake items, 12 describe work that is shaped or finished.

The decision of 2026-09-15 is that the brief replaces the line at triage. The half that makes that safe is the state rule. Today any brief at all is shaping done: `resolveTask` reaches `hasBrief` and reports `groomed` with "brief on disk; no plan yet", without ever consulting `lintBrief`. But `reggie triage` writes a scaffold. Measured: a scaffold prefilled from an intake line fails `lintBrief` with six errors, four of them `placeholder text still present in ## <section>` for Why now, Suspected area, Open questions and Not this; a scaffold with no line to prefill from fails with seven, adding the Problem section and taking the slug as its title. Moving the deletion on its own would let `reggie triage --all` empty intake in one command and report a column of untouched drafts as shaped work, with the raw wording gone.

So the two halves land together, and the rest is telling the truth in the places that still describe the old rule: the `STATE_MACHINE` constant in `tasks.ts` and the client's hand-written copy of it in `ui/board.js`, the `INTAKE_HEADER` and `REGGIE_README` templates in `layout.ts` and this repo's own copies of both, the generated instruction block in `docs.ts` that writes "intake line = ungroomed, `brief.md` = groomed" into every onboarded repo's `CLAUDE.md` and `AGENTS.md`, the API contract, the tasks page spec, the structure document, the two READMEs and the getting-started page.

## Approach
Give `brief.ts` one exported predicate, `briefDraft(content)`, that answers "is this still triage's scaffold" and returns a reason naming what is missing, then make `resolveTask`'s `hasBrief` branch consult it: a draft reports `ungroomed` with the reason naming the draft, anything else keeps today's `groomed` and today's reason string verbatim. Move the deletion into `scaffoldBrief`, after the write succeeds and only when it wrote, so the line and the brief are never both absent; teach it to prefill the Problem from every intake item carrying the slug rather than the first, and to fall back to the existing brief's title and Problem under `--force`, because after this change the brief is the only place the original words live. Widen `removeFromIntake`'s matcher to the bullet shapes `parseIntake` already accepts, so a hand-written line is removed rather than silently left. Then correct every description, stop `POST /api/intake` re-creating a line it cannot own, and sweep the 12 stale lines with the verb that now exists for exactly that.

The rejected alternative is the one the brief raises first: take the line only once the brief passes `lintBrief`. It reads well — the line survives exactly as long as the item is unshaped — but Reggie derives state and stores none, so there is no moment and no watcher where "the lint just started passing" could be noticed; it would have to be a check bolted onto some later command, which is the same forgettable-verb problem `plan done` already is. Removing at scaffold time needs no watcher, and the draft rule keeps the item in the ungroomed column, so nothing leaves the queue — it only moves from a file to a card.

The second rejected alternative is dropping any failing brief back to `ungroomed` rather than only an unfilled scaffold. The owner ruled on that (see Assumptions), and the measurement supports the ruling: a brief written out in full but left on `size: unset` fails with two front-matter errors and no placeholder error, so the two cases are cleanly separable in the lint output.

## Assumptions
- Which lint failures drop a task back to `ungroomed`: only an unfilled scaffold — placeholder text still present, or an empty Problem. A brief missing size or priority stays `groomed` with the lint reason on the card. Answered by jacobpress on 2026-09-15 in the brief; binding, not mine to revisit. The measurement confirms the two cases are separable: a prefilled scaffold fails with four `placeholder text still present` errors and a hand-written brief missing only size fails with two front-matter errors and no placeholder error.
- Triage takes the line when it scaffolds, not when the brief later passes its contract. The owner's framing sentence is "the intake line leaves at triage", which is the literal reading, and Reggie stores no state and runs no watcher, so "the moment the lint starts passing" is not a moment anything could observe — it would have to be bolted onto a later command, which is the same forgettable verb `plan done` already is. The draft rule is what makes it safe: the item does not leave the queue, it moves from a file to the ungroomed column. Rejected: waiting for a clean lint.
- `reggie plan done` is kept, with its description reworded to "Remove an intake line that outlived its brief; triage now does this". Retiring the verb would touch `packages/reggie/README.md`, `docs/getting-started.md` and anything a session has memorised, and it is the only tool that can clean the 12 stale lines this repo is carrying tonight — so tonight is the week it is most useful, not least. Rejected: deleting the command; also rejected: renaming it, because the rename costs the same two documents and buys only a better noun.
- The brief rule and the plan rule are one story, and the story is that a document earns a state by saying something, while a contract gates readiness. A plan draft that fails `lintPlan` holds at `groomed` because the *brief* earned `groomed`; a brief draft that is still the template holds at `ungroomed` because nothing earned anything. Neither rule ever advances a card on a failing document. The asymmetry the brief worries about is narrower than it looks: `planned` means "a builder can follow this", which is what a contract can test, whereas `groomed` means "somebody has said what this is", which only emptiness can disprove. Rejected: making a failing brief hold at `groomed` for symmetry, which is exactly the silent promotion this task exists to stop.
- `--force` with no intake line falls back to the existing brief's `title` and its `## Problem`, when that Problem is not a placeholder; an explicit `--title` still wins. Measured: without this, `--force` after the line is gone writes the placeholder into Problem and takes the slug as the title, which also demotes the card to `ungroomed` under the new rule — two losses from one flag. After this change the brief is where the captured words live, so it is what a rewrite must read. Rejected: refusing `--force` when there is no line, which would make the flag useless for exactly the briefs it was added for.
- The web form that appends answers to a line refuses, with 409 naming the brief, for a task that has one, and the task page stops offering it there. Measured: today it re-creates the line triage removed and the card's age comes back with it. Routing answers into the brief's Open questions section is a different endpoint and a different shape, and `needs-you-queue`'s own brief already claims it ("Answer open questions in place, appended under the brief's questions section"), so it belongs there. Rejected: letting the form keep writing, which would rebuild the file this task empties.
- An ungroomed card with no line ages from the brief's `created` front matter, after `lastActivity` and the intake date. Measured: all six currently-groomed cards report `age: null` without the fallback, and `derive-the-journal` is the only card on the board whose number changes with it (3 days → 1). Rejected: leaving `age` null, which would make a whole column read "no recorded activity"; also rejected: writing the capture date into the brief, which would add a field to the brief contract and the brief says that contract is out of scope.
- The removed wording is not archived anywhere outside git. Triage already prefills `## Problem` from the line, so the words move into the brief rather than being destroyed — measured: title, problem and detail all survive the removal. The plan closes the one case where they would not, by prefilling from every line carrying the slug rather than the first, and by removing only after a successful write. Rejected: a "done" section at the bottom of `intake.md`, which reintroduces the log-of-everything this task is removing; rejected: copying the raw line into the brief's front matter, which nothing would read.
- One thing outside this repo does expect the old rule, and it is the widest-travelling copy of all: the generated instruction block in `docs.ts` writes "Task state is read from git: intake line = ungroomed, `brief.md` = groomed …" into the `CLAUDE.md` and `AGENTS.md` of every repo Reggie onboards, so every session in every such repo reads it first. Both halves of that sentence become wrong here, and it is corrected with the others. `reggie docs refresh` then runs in the same commit, on a clean tree, so `reggie docs check` in CI stays green — the existing gotcha in `CLAUDE.md` warns that the check counts untracked files. Checked and needing nothing: the MCP resource `reggie://intake` is already described as "Raw items waiting for triage", which the change makes more true, and the MCP capture tool makes no claim about a line's lifetime.
- `removeFromIntake`'s matcher is widened in this task rather than captured separately. The intake header invites hand-written lines and says no structure is required, and `parseIntake` and `addIntakeDetail` already accept `*`, `+`, checkboxes and up to three spaces of indent while `removeFromIntake` accepts none of them. Measured: four of five hand-written shapes are silently left behind. Today that is a cosmetic miss at `plan done`; after this change it is a line that stays in the queue for an item the board reports as shaped, which is precisely the drift being removed. Rejected: shipping the move and capturing the matcher, because the acceptance criterion "every slug left in intake is ungroomed" would then be false for any repo whose owner types their own bullets.
- The 12 stale lines are swept in this task, in their own commit, using `reggie plan done`. Otherwise the reworded header would be a false statement printed at the top of the very file that disproves it. The sweep is measured and reversible: 65 items → 53, no state changes, one age change, no blank-line runs left behind, and the file still ends with a single newline. Rejected: leaving the sweep to a later cleanup, which would leave the first reader of the new header looking at twelve counter-examples.
- The brief's front matter says `size: small` and `risk: low`; this plan is neither. Twenty-nine files is not small, and `reggie plan risk` reads `docs/ui-api-contract.md` against the `api` pattern and returns `medium`, which is what the front matter above now says. Most of the count is one-line wording in documents, and the behaviour change is roughly sixty lines across six modules, so the shape is still a small change with a long tail of descriptions — but the number a reviewer sees is the computed one, not the brief's guess, and the guess was made before anyone counted the places that describe the rule.

## Bail conditions
- If any task currently on the board changes state under the new rule — that is, if `evidence/board-diff.txt` is not empty — stop. Seventeen briefs pass `lintBrief` today and the derivation is supposed to be a no-op on this repo; a single relabelled card means `briefDraft` is catching something the owner's ruling did not intend.
