# Derive a journal entry from a task's commits and its Claude session's closing words, with an explicit verb; first slice, Claude only

## Problem
The journal is the story the web view tells about the work, and it exists only when a session remembers to write it. The 2026-09-13 decision says the journal is derived, and the 2026-09-15 decision says how it is triggered: an explicit verb, `reggie journal derive <slug>`, for a task in flight and for a finished one. Nothing in `packages/reggie` reads a transcript today, nothing reads a launch record back (`recordLaunch` has no reader anywhere in `src/` or `ui/`), and `journal.ts` has one writer shape and no way to tell a machine-written entry from a hand-written one.

The brief warns that the transcript layout on this machine does not match the intake note. It was measured on 2026-09-17, read-only, structure only, before this plan was written. What is true:

- **Where a Claude transcript lives.** `~/.claude/projects/<folder>/<session id>.jsonl`, a flat file named by the session id. The folder is keyed by the directory the session was *started* in, with every character that is not a letter or a digit turned into a dash, so the encoding cannot be reversed (a space, a slash and a dot all become the same dash). Every one of the 235 transcripts on this machine is named by the `sessionId` its own records carry; none carries two ids. The session-id *folder* the brief saw under this worktree's project folder is not a transcript: a session leaves `<session id>/workflows/` in the project folder of every directory it later changed into, and `<session id>/subagents/` and `<session id>/tool-results/` beside the real transcript. All ten sessions that worked on this repo were started one level above it, so their transcripts sit in the workspace's project folder, not in this worktree's. The only reliable key is the id: look for `<id>.jsonl` in every project folder.
- **What a record is.** One JSON object per line, 20 record types seen. Only `user`, `assistant`, `attachment` and `system` records carry a `cwd` and an `isSidechain` flag. 45,304 of 45,305 assistant records carry exactly one content block (one carries three): `thinking`, `tool_use` or `text`, with the API message's `stop_reason` beside it. Of 7,962 assistant text records, 6,343 are interim commentary (`stop_reason: tool_use`), 1,561 close a turn (`end_turn`), 54 end on `stop_sequence` and 4 carry no reason. Of 1,620 turns, 1,542 close on an `end_turn` text record, 54 on a `stop_sequence` one, 19 have text only before their last tool call, and 1 has no text at all.
- **What must never be read into the repo.** `user` records hold the owner's prompts and every tool result; `queue-operation` holds queued prompts; `last-prompt`, `custom-title` and `ai-title` hold the owner's words or a summary of them; `attachment` holds file contents and instructions; `bridge-session` holds the owner's account and organisation ids; `thinking` blocks hold reasoning. A transcript record also has a `slug` key of its own, which is the tool's nickname for the session and not a Reggie task.
- **Sidechains.** Subagent work is not in the main file. It is in `<session id>/subagents/agent-<id>.jsonl` (775 such files here), every record `isSidechain: true` with the parent's `sessionId`, and a `.meta.json` beside it. Zero main transcripts contain a sidechain record.
- **Resume and compaction.** A resumed session appends to the same file under the same id: one transcript here carries two tool versions, and 70 of 235 span more than one UTC day. Compaction does not rewrite the file: it appends a `system` record with `subtype: compact_boundary` and then a `user` record with `isCompactSummary: true`, whose text paraphrases the whole conversation, the owner's side included. 5 of 235 files have one.
- **Size.** 579 MB in total; the largest transcript is 39 MB and 3,118 lines; the longest single line is 13.4 MB (a tool result). The longest line that holds an assistant text block is 74 KB. A bounded, synchronous, chunked read of the 39 MB file with a 1 MB line ceiling took 112 ms in Node with under 110 MB resident, skipping two oversized lines, neither of which could have held eligible text.
- **Damage.** Zero unparseable lines, zero NUL bytes and zero invalid UTF-8 in 235 files, including the transcript of the session that was writing while it was measured. 120 `user` or `assistant` records are out of timestamp order, so file order is not time order.
- **The one join from a slug to a transcript does not exist here yet.** There is no `.reggie/.cache/launches/` folder in this checkout: no session has ever been started through `reggie launch --run` or the launch button. All thirteen committed claim files say `session: session` (or nothing), because they were made from inside a session and `sessionName` returns the placeholder. So on this machine, today, no task can be joined to a transcript by anything Reggie recorded. `recordLaunch` also writes one file per slug and overwrites it, so a plan launch followed by a build launch keeps only the build's id, and the record names no person.
- **Codex.** `~/.codex/sessions/<yyyy>/<mm>/<dd>/rollout-<local start time>-<id>.jsonl`, 2,013 files, the largest 353 MB. The folder date and the file-name time are local time (four hours behind the UTC stamp inside, measured on all 462 September files). The first line is a `session_meta` record of 19 to 50 KB with `cwd`, `git.branch`, `id`, and for subagent threads `forked_from_id` and the parent's `session_id`. Only four September rollouts have a working directory inside this workspace, none in a task worktree, none from a Reggie launch. There is no real case on this machine to check a directory-and-time match against.

Two facts about the journal's own readers shape the entry. The web view renders entry text through `inline`, which makes text nodes, code spans, bold and `[[route|label]]` links; and the task page turns any evidence item that has no slash into a link to the evidence route, so a bare commit id in `evidence:` would render as a link that answers 404. And `landTask` refuses to merge while the base checkout has uncommitted changes to tracked files, so an entry appended to an existing day file and left uncommitted blocks the next landing until it is committed, exactly as a hand entry does today.

## Approach
Build the verb and the function it wraps in three new modules, keep every transcript-facing rule in one place, and let nothing reach the journal that did not pass a whitelist, a flattener, a redactor and a length cap. The task is large, so it is split, and this plan is the first slice, which stands alone: Claude sessions, commits, the template, idempotence, the privacy rules, the opt-in rewrite seam, and the docs wording. Reading Codex rollouts and reading subagent transcripts are separate captured items (`derive-reads-codex-sessions`, `derive-reads-subagent-transcripts`); the pass inside `reggie serve` was already out of scope in the brief.

**The precursor has not landed, and this plan does not absorb it.** `session-name-reads-real-id` is still an ungroomed intake line. Derive reads only what is recorded today and treats a session field as usable only when it is shaped like a UUID. It finds a slug's sessions from four places, in this order, deduplicated by id: the launch log (below); the `session` field of the task's claim file, read from the working tree and else from the task branch; the names of journal day files that end in a UUID and hold an entry for the slug; and an explicit `--session <uuid>` flag. The second and third yield nothing today and start yielding the moment the precursor lands, with no change to derive. What is lost until then is said plainly in the verb's output and in the docs: a session that was not started through `reggie launch` has no recorded id, so its transcript is never found on its own and the entry is drawn from commits alone unless the person names the session; a hand entry written from inside a launched session still goes to the shared `<person>-session.md` file while the derived entry for the same session goes to `<person>-<session id>.md`; and a commits-only entry goes wherever `sessionName` says, which is the shared file until the precursor lands.

**The launch log.** `recordLaunch` keeps writing `.reggie/.cache/launches/<slug>.json` (the documented latest record) and also appends the same object as one line to `.reggie/.cache/launches/<slug>.log`, so every launch for a slug survives. A new `readLaunches(root, slug)` reads the log, skips lines that do not parse, and falls back to the single `.json` for records written before this lands. Derive reads the cache of the checkout it runs in, and, when that checkout is a task worktree Reggie made (`<parent>/.worktree/<slug>`), the parent's cache too, because launches are recorded by the serving checkout. A record with `tool: codex` has no id; this slice reports it as a Codex session that was not read and never guesses by time.

**Finding and reading a transcript (`transcript.ts`).** The Claude home is `CLAUDE_CONFIG_DIR` when set, else `~/.claude`, and it is a required argument of the library function: only `cli.ts` supplies the default, so no test can reach the real home without naming it. An id that is not a UUID is refused before any path is built. The transcript is the file `<id>.jsonl` found in any folder under `projects/`; the encoded folder name is never computed. A launch record whose start directory no longer exists changes nothing, because the directory is never consulted. The file is read through a synchronous chunked line reader (64 KB buffer, newline byte scan, a 1 MB ceiling per line): a line over the ceiling is dropped without being assembled and counted, a line that does not parse is counted and skipped, and the file is never read whole. Each line is decoded as UTF-8 with replacement. The reader understands exactly these fields and no others: `type`, `isSidechain`, `timestamp`, `cwd`, `message.stop_reason`, and the `type` and `text` of each block in `message.content`.

**Which text is eligible.** One kind of record only: `type: assistant`, not a sidechain, with `stop_reason: end_turn`, and from it only its `text` blocks. That is the assistant's closing message of a turn, which is the owner's ruling ("the closing assistant turns") made exact by measurement. Never eligible: anything in a `user` record (prompts, tool results, the compaction summary), `thinking`, `tool_use` inputs, interim text, attachments, queue operations, titles, last prompts, bridge records, subagent files, the `tool-results` folder. Two location rules narrow it further, by lexical path comparison so a released worktree still matches: a record counts only when its `cwd` is inside the repository (its `.worktree/` task worktrees included), and when any record of the session has a `cwd` inside the slug's own worktree, only records inside that worktree count. A session named with `--session` that never worked inside the repository is refused and nothing is written.

**How much, and what is stripped (`redact.ts`).** From the records newer than the watermark, only the newest eligible message is quoted; the entry says how many other closing messages the span held. The message is flattened: fenced code blocks and table rows are dropped; heading, list, quote and emphasis markers and backticks are removed; a markdown link keeps its label; a URL loses its userinfo, query and fragment; `[[` is broken apart so the web view's link syntax cannot be forged; NUL, the other C0 controls, DEL and the bidirectional control characters are removed; all whitespace, newlines included, collapses to single spaces. Because the quote is one line that never begins a line of the file, it cannot forge an entry header, a trailer or a front-matter fence; `escapeBodyLine` learns the new trailer as a second guard. Then it is redacted: provider key shapes (`sk-`, `ghp_`, `github_pat_`, `xox?-`, `AKIA`, `AIza`), PEM blocks, JWT-shaped triples, `Bearer` values, any `name=value` or `name: value` whose name contains secret, token, password, passwd, api key or credential, base64-like runs of 40 or more characters that mix cases and digits, email addresses, and absolute or home-relative paths. Each hit becomes a fixed bracketed word, the entry ends with a sentence saying how many passages were withheld, and the verb prints the count. Last, the quote is cut to at most 800 characters at a sentence end and marked as cut. The stance is that text bound for git is filtered by kind first and by pattern second, and that neither is a guarantee: an assistant can repeat the owner's words in its closing message, no pattern catches that, and the review point is that the verb never commits, never pushes, prints every character it wrote, and has `--dry-run`.

**The commits.** A task with a live branch (`TaskInfo.branchRef`) is read as `base..branchRef` through `historyLogArgs` and `parseNumstatLog`. Otherwise `taskLanding` from `history.ts` is reused as it stands: with a landing merge the commits are the branch side of the merge, without one they are the indexed commits that name the slug, which covers a fast-forward landing. Merges and the `meta: claim` commit are left out, because the claim, release and decide steps already write their own entries and derive never narrates them again. Each new commit is given to the session whose first-to-last record span contains its author date; a commit inside no span goes to one commits-only entry.

**The entry.** The template writes listener-register sentences from the facts: what it was derived from, how many commits over which stretch changed how many files with up to five subjects quoted, the one transition the session's goal produces read from the task's state now (a shaping session: whether the brief is written; a planning session: whether a plan passes the contract; a build: whether the packet is written; a discussion: nothing), then the closing quote or the fixed sentence for why there is none. The degraded-case sentences are exported constants so tests and reviewers can check them. No commit id and no file path appears in the prose. The entry is attributed to the claim's handle when the task has a claim and else to the person running the verb, with tool `claude` for a session entry and `reggie` for a commits-only one; the stage is `triage`, `plan`, `discuss` or `execute` by launch goal, `session` for a session named by flag with no record, and `commits` for commits alone. It is dated at the last moment it covers, in local time, so a session that ran past midnight is filed under the day it ended and says both days in words. It goes through `appendJournal` into the existing day-file scheme: `<date>/<person>-<session id>.md` for a session, one file per session and no slug-named file, which is the owner's ruling. `evidence:` carries only repository-relative files under the task's own folder that the covered commits touched (the packet and up to eight evidence files), or the brief or plan for a session without commits. The transcript path is never written anywhere.

**Idempotence.** The watermark lives in the entry, because that is the only place that travels with git, survives a merge, a released branch and a cleared cache, and is never a file two people share. `appendJournal` gains an optional `derived` mark written as a last line, `derived: session=<uuid or none> through=<ISO instant or none> commits=<12-hex ids, comma separated, or none> prose=<template or model>`, and `parseJournalFile` reads it into `JournalEntry.derived` and keeps it out of `text`; the header format and everything about a hand entry are untouched. A run collects the marks of every derived entry for the slug from the working tree and, when the task branch is live, from the journal files that branch changed (read with `fileAtRef`). New means a commit whose id is in no mark, and an eligible record whose timestamp is later than the latest `through` for that session; timestamps are compared as instants and file order is not trusted. `through` is the latest timestamp among eligible records read, so an unfinished last line is never counted as covered. With nothing new the verb appends nothing and says so.

**The opt-in rewrite.** `--rewrite` makes one headless call per entry written, and it is off by default. What is sent is a fixed instruction followed by exactly the characters of the template body that would otherwise have been written, already flattened, redacted and capped: the call sees nothing that was not already bound for git. It goes to the session's own tool and never across vendors; in this slice that is `claude -p --tools "" --no-session-persistence --strict-mcp-config` with the prompt on standard input, run from the OS temp directory with a 120 second limit, under the owner's existing Claude Code login. A commits-only entry is never sent. The reply passes through the same flattener, redactor and cap, the mark says `prose=model`, and any failure (the tool is not installed, a non-zero exit, a timeout, an empty or oversized reply) writes the template entry instead and prints the reason. The runner is an injected function: the library has no default, `cli.ts` builds the real one, the real one throws when `VITEST` is set, and the tests use a fake. Headless `claude -p` is denied in the build environment, so the real call will not have been run by anyone when this lands; the flags above were read from `claude --help` on 2.1.261 and nothing more. The packet must say so.

**The verb.** `reggie journal derive <slug> [--session <uuid>] [--dry-run] [--rewrite]`. It appends and reports: the entry in full, the file it went to, a reminder that the file is uncommitted and that the next landing will refuse until it is committed, and a last line that is a content-free summary (sessions found and not found with the reason, records read, lines skipped as oversized or unparseable, eligible messages, characters quoted, passages withheld, commits covered, milliseconds). `--dry-run` prints the same and writes nothing. It never commits and never pushes.

**The wording question.** The generated block and the context pack keep asking for one hand entry per step, reworded to say what the verb adds and what it cannot: it fills in the commits and a launched session's closing words, not the reasons and not what is uncertain. Dropping the request now would empty the journal, because measured today derive can find no transcript for any task on this machine. When to drop it is captured as `when-sessions-stop-being-asked-for-a-hand-entry`.

Rejected alternatives. Computing the project folder from the start directory: the encoding is lossy and was only observed for slashes, spaces and dots, while the id is unique and costs one directory listing. Reading the compaction summary as the session's own summary: it is a `user` record that paraphrases the owner's prompts. Quoting every closing message in the span: more private text for little more story, and a re-run picks up later messages anyway. A watermark file in the task folder or the cache: the first is a shared file that a branch and the base both edit, the second is uncommitted and machine-local. Commit ids in `evidence:`: measured, the task page would draw each as a dead link. A sixth header field to mark a derived entry: `HEADER_RE` ends in a lazy group, so an older reader would fold it into the stage. Matching a Claude session by directory and time when no id is recorded: on this machine one session works in many task worktrees, so the guess would quote the wrong task's conversation. Committing the entry from inside the verb: `journal add` does not, and the uncommitted entry is the review point.

## Acceptance criteria
- [ ] AC1 Given a session id, the transcript is found as `<id>.jsonl` in whichever folder under `<claude home>/projects/` holds it, including when the launch record's `cwd` names a directory that no longer exists; a folder that holds only a `<id>/workflows/` directory is not taken for a transcript.
- [ ] AC2 A session id that is not shaped like a UUID (`../x`, `session`, an empty string, a UUID with a trailing slash) is refused before any filesystem path is built from it, from the launch log, the claim, a journal file name and the `--session` flag alike.
- [ ] AC3 From a fixture transcript that holds a distinct marker string in a user prompt, a tool input, a tool result, a thinking block, an attachment, a queue operation, a last-prompt record, a title record, a compaction summary, a sidechain assistant text, an interim assistant text with `stop_reason: tool_use`, and one assistant text with `stop_reason: end_turn`, the derived entry contains the `end_turn` marker and none of the other eleven.
- [ ] AC4 A transcript whose eligible records are split between the slug's own worktree, another task's worktree and a directory outside the repository yields a quote taken only from the record inside the slug's worktree; a session named with `--session` that has no record inside the repository is refused with exit 1 and no file is written.
- [ ] AC5 The line reader, run with a 16 byte chunk, returns every line of a fixture byte-for-byte, including a line holding a four-byte UTF-8 character that straddles a chunk boundary, and a line longer than the ceiling is reported as oversized without being returned.
- [ ] AC6 `transcript.ts` contains no call to `readFileSync`, `readText` or `readFile`, and deriving from a generated fixture transcript of at least 8 MB that includes one 3 MB line completes inside the suite with that line counted as oversized and the entry still written.
- [ ] AC7 A transcript whose last line is cut off mid-object derives from the lines before it, counts one unparseable line, and records a `through` no later than the last complete eligible record; after the line is completed and the verb is run again, the message on that line is quoted in a second entry.
- [ ] AC8 A transcript containing a raw NUL byte on one line, invalid UTF-8 bytes on another, and an escaped ` ` and a right-to-left override inside an eligible text produces a journal file that is valid UTF-8 and contains no NUL, no other C0 control except newline, and no bidirectional control character.
- [ ] AC9 A transcript with a `compact_boundary` record, a following `isCompactSummary` user record, records carrying two different tool versions, and an eligible message after the boundary quotes the message after the boundary and nothing from the summary.
- [ ] AC10 A session whose transcript has no eligible record at all, and a session whose newest turn ends on tool calls with no closing text, each produce (when the task has new commits) an entry carrying the exported sentence for that case and no quotation; with no new commits either, nothing is appended.
- [ ] AC11 Two launches recorded for one slug are both returned by `readLaunches`, `<slug>.json` still holds the later one, a malformed line in the log is skipped, and a cache that holds only an old single `<slug>.json` with no log is still read.
- [ ] AC12 The sessions for a slug are the union, without duplicates, of the launch log, a UUID-shaped `session` in the claim file (from the working tree or the task branch), journal day files named `<person>-<uuid>.md` that hold an entry for the slug, and `--session`; a claim whose session is the word `session` contributes none.
- [ ] AC13 A launch record with `tool: codex` and `session: null` is reported in the verb's output as a Codex session that was not read, the entry (when there are commits) carries the exported sentence for it, and no session is guessed by directory or time.
- [ ] AC14 A claim whose `machine` differs from this host, with no transcript found, yields an entry carrying the exported sentence that the session ran on another machine; a recorded id whose transcript is missing on this host yields the exported sentence that no transcript was found.
- [ ] AC15 For a task with a live branch the commits narrated are exactly those in `base..task/<slug>` that are not merges and are not the `meta: claim` commit, including when the branch has merged the base back into itself.
- [ ] AC16 For a done task whose branch is deleted, the commits narrated are the branch side of the merge `taskLanding` finds, and the merge commit itself, the claim, the release and the decision are not narrated.
- [ ] AC17 For a done task that landed by fast-forward, with no merge and no branch, the commits narrated are the indexed commits that name the slug.
- [ ] AC18 A task with no commits and no readable session (a shaped task nobody launched) appends nothing, prints a sentence saying there is nothing to derive, and exits 0; a task with no commits and one launched planning session derives an entry from the transcript and the plan's state, with stage `plan`.
- [ ] AC19 Two sessions for one slug on one day produce two day files, one per session id, each holding one entry, and each commit appears in exactly one entry: the one whose session span contains its author date, or a single commits-only entry when no span does.
- [ ] AC20 A session whose covered span runs from 23:40 on one local day to 00:20 on the next is written as one entry in the later day's folder, timed 00:20, and its prose names both days.
- [ ] AC21 A derived entry is written into `.reggie/journal/<date>/<person>-<session id>.md`; a commits-only entry is written into the file `sessionName` names; no run creates a file whose name contains the slug.
- [ ] AC22 `parseJournalFile` returns a derived entry with `derived` set to the session, the `through` instant, the commit ids and the prose kind, and with `text` free of the mark; every test already in `journal.test.ts` passes unmodified, and a hand entry whose body has a line beginning `derived:` is written with that line indented and parses with `derived` unset.
- [ ] AC23 Running the verb twice with nothing new leaves every file under `.reggie/journal/` byte-identical after the second run and prints that there is nothing new.
- [ ] AC24 After two further commits and one further closing message, a second run appends one entry that names only the two new commits and quotes only the new message, and its mark lists only those two commit ids.
- [ ] AC25 An entry derived and committed on the task branch in the task's worktree is seen by a later run in the serving checkout, which appends nothing.
- [ ] AC26 An eligible message containing a line shaped like an entry header for another slug, a `## ` heading, a `---` line, an `evidence:` line, a `derived:` line, a fenced code block and `[[task/other|label]]` yields exactly one parsed entry for the slug, no entry for the other slug, the evidence and mark that derive itself set, no text from inside the fence, and no `[[` in the file.
- [ ] AC27 An eligible message holding one example of each redacted shape (the six provider key prefixes, a PEM block, a JWT-shaped triple, a `Bearer` value, `API_KEY=...`, `password: ...`, a 48-character mixed base64 run, an email address, a `/Users/...` path, a `~/...` path, and a URL with userinfo and a `?key=` query) leaves none of those values in the journal file, the entry ends with the sentence giving the number withheld, and the verb prints the same number.
- [ ] AC28 A 40-character lowercase hex string and the word `token` used in a sentence without a value are not redacted.
- [ ] AC29 The quotation in any entry is at most 800 characters, ends at a sentence end when the message has one inside the limit, and is marked as cut when the message was longer; the entry states how many other closing messages the span held.
- [ ] AC30 No journal file written by the verb contains an absolute path, the Claude home, a transcript file name, or a commit id outside the `derived:` line; `evidence:` holds only repository-relative files under `.reggie/tasks/<slug>/`.
- [ ] AC31 A session entry is attributed to the claim's handle when the task has a claim and to the current person otherwise, with tool `claude` and the stage mapped from the launch goal (`triage`, `plan`, `discuss`, `execute`, or `session` for a flag-named session); a commits-only entry has tool `reggie` and stage `commits`. `parseClaim` returns the claim's `handle`.
- [ ] AC32 After a run the repository's HEAD is the commit it was before, nothing is staged, and the output names each journal file it wrote as uncommitted; `--dry-run` prints the same entry and summary and leaves `git status --porcelain` unchanged.
- [ ] AC33 Without `--rewrite` the injected runner is called zero times; `deriveJournal` called with `rewrite: true` and no runner writes the template entry and reports why.
- [ ] AC34 With `--rewrite` and a fake runner, the runner is called once per entry written, its input is the fixed instruction followed by exactly the template body that a run without the flag writes (byte-equal), its argument list is `claude -p --tools "" --no-session-persistence --strict-mcp-config`, its working directory is the OS temp directory, and a commits-only entry never reaches it.
- [ ] AC35 A fake reply containing a secret-shaped value, an entry-header-shaped line and 3,000 characters is written redacted, on one line and cut to the limit, with `prose=model` in the mark.

## Assumptions
- Template by default over commits, transitions and the closing assistant turns, with an opt-in flag for one headless model call over the same assembled facts. Answered by jacobpress on 2026-09-15 in the brief; binding. Made exact here: "the same assembled facts" means the call receives the template body character for character and nothing else, and "one call" means one per entry written.
- The existing day file with the real session id in its name, one file per session, no slug-named files. Answered by jacobpress on 2026-09-15; binding. The id is the full UUID. A commits-only entry has no session of its own and goes to the file `sessionName` names, which is the shared file today and the deriving session's own file once the precursor lands.
- All launched sessions for the slug, whatever their goal; a session without commits derives from its transcript and the transition it produced. Answered by jacobpress on 2026-09-15; binding. Measured: today's launch record keeps only the latest launch per slug, so honouring "all" needs the launch log this plan adds. "The transition it produced" is read from the task's state at derive time by goal, not reconstructed from the conversation.
- The `sessionName` precursor is its own slice, `session-name-reads-real-id`. Answered by jacobpress on 2026-09-15; binding. It has not landed and is not absorbed. Derive treats only UUID-shaped session fields as ids and reads `CLAUDE_CODE_SESSION_ID` nowhere; the variable exists in a Claude Code session's environment on this machine (checked by name only), which is the precursor's business.
- What the session's own summary messages are: assistant text records with `stop_reason: end_turn`, outside sidechains. Chosen because it is one field test, it matched 1,542 of 1,620 measured turns, and it excludes the 6,343 interim commentary records. The 54 turns that end on `stop_sequence` are not eligible, because nothing measured says what ends a message that way; such a turn is reported with the no-closing-words sentence. Rejected: everything after the last tool call (needs turn reconstruction for the same answer), the compaction summary (a user record paraphrasing the owner), messages that name the packet (content matching on private text).
- Only the newest eligible message in the span is quoted, at most 800 characters. The owner's phrase was plural; one message is the smallest amount of private text that still carries the session's own conclusion, a re-run during a long task picks up later messages one at a time, and the entry says how many it did not quote. 800 characters is about 45 seconds read aloud; measured, the median closing message is 146 characters and the 95th percentile 3,082. Rejected: quoting the last three within one budget.
- Where the transcript lives: found by id across every project folder, never by encoding the start directory. Measured above.
- The watermark lives in the entry as a `derived:` last line. It survives a merge, a released branch and a cleared cache, and is never a file two writers share. Rejected: the launch record (uncommitted, machine-local, overwritten), a file in the task folder (edited on the branch and on the base, so it conflicts), byte offsets (timestamps survive a moved file and need no second bookkeeping).
- The person on a session entry is the claim's handle when the task has a claim, else the person running the verb. Transcripts are machine-local, so whoever can read one is in practice who ran it; the decide entry already names whoever merged. A launch record names no person; that gap is captured, not fixed here.
- Derive narrates no transition that already writes its own entry: claim, release and decide are skipped, and the claim commit and the landing merge are left out of the commits. It states one transition per goal from the task's present state.
- Evidence on a derived entry is repository-relative files under the task's folder that the covered commits touched, the packet first and at most eight evidence files, or the brief or plan for a session without commits. Commit ids go in the mark, not in `evidence:`, because the task page draws a slash-free evidence item as a link to the evidence route (measured in `board.js`); that behaviour is captured. The transcript path never counts as evidence and is never written.
- With the transcript gone and the commits present, derive writes a commits-only entry that says no session was found; with neither, it writes nothing and says why. Refusing outright was rejected because every task landed before this ships is in that state.
- The merge is re-found by `taskLanding` on every run; no merge id is recorded at decide time. The lookup exists, is reused by the branch diff, and a probe run against this repository found the landing merge of all thirteen landed tasks.
- The verb appends and reports, prints the whole entry, and has `--dry-run`; it never commits. The later serve pass needs append; the review point in the untrusted weeks is the uncommitted file and the printed text. The output says that an uncommitted entry in a tracked day file makes the next landing refuse until it is committed, which is measured behaviour of `landTask` and the same as a hand entry today.
- Team mode: a machine that does not hold the transcript writes commits-only entries and says the session ran elsewhere, using the claim's `machine` field. Nothing from a transcript is committed except through the entry. Rejected: committing a transcript summary beside the packet, which is a second channel for private text.
- The instruction block keeps asking for a hand entry per step in this task, reworded to name the verb and its limits. Measured reason: no launch record exists and no claim carries a real id on this machine, so derive alone would leave most tasks with a commit list. The decision about when to stop asking is captured.
- Codex is split out. Measured: rollouts are matched by directory and local-time window only, the first line alone is up to 50 KB, the largest file is 353 MB, and this machine has no Codex session from a Reggie launch or in a task worktree to check a match against. This slice names a Codex launch as unread and never guesses. Captured with the measurements as `derive-reads-codex-sessions`.
- Subagent transcripts are not read. Measured: an orchestrated build's real closing report lives in a separate sidechain file; a session started by `reggie launch` is a main session whose own closing message is in the main file. Captured as `derive-reads-subagent-transcripts`.
- `--session <uuid>` is added although the brief does not name it. Without it nothing on this machine can exercise the transcript path for real, since no id was ever recorded, and it is the honest manual join until the precursor lands. It is guarded by the inside-the-repository rule so it cannot be pointed at an unrelated conversation.
- The redaction stance: kind first, pattern second, neither a guarantee. Eligible text is the assistant's closing prose only, which is not where secrets usually sit (they sit in tool results, file contents and prompts, none of which is ever read). The pattern pass errs toward withholding. What no pattern catches, such as the assistant repeating something private the owner said, is left to the uncommitted-file review point and is said in the docs.
- The rewrite goes only to the session's own tool, so text a Claude session produced is sent to Claude and never to another vendor; a commits-only entry is never sent. The flags were read from `claude --help` on version 2.1.261 and have not been run. `--tools ""` and `--strict-mcp-config` are there so the headless session has nothing to act with, and the temp working directory so it loads no project instructions.
- Entry dates are local time, like every other journal date, and tests pin `TZ=UTC`. Temp repositories resolve through a symlink on macOS (`/var` to `/private/var`), so fixtures write `cwd` values from the same resolved root the code compares against.
- `JournalEntry.derived` is an additive optional field on existing payloads; `ClaimInfo.handle` likewise. Checked: test files are excluded from the typecheck, and no reader enumerates the fields of either.
- The brief's front matter says `risk: low`. The front matter above carries whatever `reggie plan risk` computes from the file list. Because the task moves private text into git, a security review is an acceptance criterion whatever the class.
- New source, test and note files move the counts in the generated block, and `docs.ts` changes its wording, so `CLAUDE.md` and `AGENTS.md` are refreshed last, on a clean tree, after `npm run build`, because the installed `reggie` refuses to run behind its source.

## Out of scope
- Reading Codex rollouts and matching one by directory and time window, including zero, one or several candidates, forks and hand-started sessions. Captured as `derive-reads-codex-sessions`. This slice only names a Codex launch as unread.
- Reading subagent transcripts, the `tool-results` folder, or anything under a session-id folder. Captured as `derive-reads-subagent-transcripts`.
- `session-name-reads-real-id`. Its own slice by the owner's ruling; still an intake line.
- The pass inside `reggie serve`, a session-end hook, an MCP tool for derive, and any route that triggers it.
- Changing the launch, build, plan or shape prompts. They keep asking for hand entries; when that stops is captured as `when-sessions-stop-being-asked-for-a-hand-entry`.
- Adding a person to the launch record or moving launch records out of the uncommitted cache. Captured as `a-launch-record-names-no-person-and-lives-only-in-the-cache`.
- How the web view draws an entry, the evidence chip's dead link for a slash-free item (captured as `a-slash-free-journal-evidence-item-becomes-a-dead-link`), and any marker for derived entries in the page.
- Matching a Claude session to a task by directory and time when no id is recorded.
- Committing or pushing the entry, a `--commit` flag, and deriving for every task at once.
- Rewriting or deleting hand entries, removing the `.gitattributes` union line, and renaming day files.
- Parsing `Co-Authored-By`, episodes, narration, session search, cost, and a transcript view.
- Running the real headless call. It is built behind a seam and stays unverified until the owner runs it.

## Bail conditions
- If a session started with `claude --session-id <uuid>` turns out to write its transcript under any name other than `<uuid>.jsonl`, stop. Every transcript measured is named by the id in its records, but no session on this machine was started through `reggie launch`, so the launched case itself is inferred and not observed.
- If the owner rules `--session` out, stop and re-plan the real-machine criteria: with the precursor unlanded and no launch record on this machine, there is then no honest way to read any real transcript, and the slice would ship a transcript reader proven only against synthetic files.
- If producing a useful entry needs any transcript field beyond the seven the reader is allowed to understand, or any record kind beyond closing assistant text, stop: widening what is read from a private conversation is a decision for the owner, not a build detail.
- If a derived entry cannot be made recognisable without changing `HEADER_RE` or how an existing hand entry parses, stop; the brief rules out changing hand entries.
- If `taskLanding` does not find the landing merge of a done task in this repository, or returns commits that are not the task's, stop: that belongs to the attribution work.
- If the bounded read of the largest real transcript takes more than 5,000 ms or cannot be done without holding the file in memory, stop and re-plan the reader; measured in a probe it took 112 ms.
- If the redaction pass withholds something from most real closing messages, or lets one of its own listed shapes through in the fixture, stop: a filter that cries wolf gets switched off, and one that leaks is worse than none.
- If the real run against `intake-line-leaves-at-triage` would put anything into the entry that is not a commit subject or one of Reggie's own sentences, do not commit it; save the content-free summary instead and say so in the packet.
- If making `--rewrite` testable needs the real tool to be run in the suite or in the build session, leave the flag out, ship the template, and capture the rewrite as its own item; the owner's default is the template.
