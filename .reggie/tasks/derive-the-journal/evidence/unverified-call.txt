The opt-in rewrite (`reggie journal derive <slug> --rewrite`): what was and was not verified. Written by the build session on 2026-09-17, before the packet; the packet is to say the same thing in its own words and quote this file.

The statement:

  The real headless call has never been run. Not by the build session, not by the tests, not by anyone. Headless `claude -p` and `codex exec` are denied by the permission system in the environment this was built in, and the build session did not attempt either. What ships is a seam: `deriveJournal` takes an injected runner and has no default, `cli.ts` builds the real runner only when `--rewrite` is passed, and the real runner throws when `VITEST` is set, so the suite cannot make the call by accident. Every rewrite test uses a fake runner.

What the flags rest on:

  The argument list is `claude -p --tools "" --no-session-persistence --strict-mcp-config`, with the prompt on standard input, run from the OS temp directory with a 120 second limit. Those flags were read from the help text of `claude` version 2.1.261 (Claude Code) on the owner's machine on 2026-09-17, and from nothing else. The help text says `--tools ""` disables all built-in tools, that `--no-session-persistence` only works with `--print`, and that `--strict-mcp-config` ignores every MCP configuration but `--mcp-config`. Whether the tool accepts that combination, reads the prompt from standard input when `-p` is given no argument, and answers with plain text on standard output is inferred from that help text and has not been observed.

What is verified, with a fake runner (evidence/rewrite-seam.txt):

  - without the flag the runner is called zero times, even when one is given
  - with the flag and no runner, the template is written and the reason is reported
  - the runner is called once per session entry and never for an entry drawn from commits alone
  - its input is the fixed instruction, a blank line, and exactly the template body a run without the flag writes, byte for byte
  - its argument list, working directory and timeout are the ones above
  - a reply holding a secret-shaped value, an entry-header-shaped line and more than 3,000 characters is written redacted, on one line and cut, with prose=model in the mark
  - a missing tool, a non-zero exit, a timeout, an empty reply, an oversized reply and a runner that throws each leave the template entry with prose=template and a printed reason
  - the real runner throws under vitest

What the owner should do before trusting the flag: run `reggie journal derive <slug> --rewrite --dry-run` once on a task with a launched session, and check that the tool starts, that the reply is a rewrite of the entry and nothing else, and that nothing is written.
