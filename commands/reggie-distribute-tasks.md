# Distribute Tasks

Parse freeform notes into discrete tasks and distribute them to the correct repos based on workspace documentation.

## Context

```bash
echo "=== Current Directory ==="
pwd

SKIP_DIRS="node_modules|target|.build|build|dist|vendor|.next|Pods|.venv|venv|__pycache__"

scan_dir() {
  local dir="$1"
  local indent="$2"
  local depth="$3"

  # Safety: max depth 6
  if [ "$depth" -gt 6 ]; then
    return
  fi

  for entry in "$dir"/*/; do
    [ -d "$entry" ] || continue
    local name
    name="$(basename "$entry")"

    # Skip hidden dirs, symlinks, and heavy dirs
    case "$name" in
      .*) continue ;;
    esac
    echo "$name" | grep -qE "^($SKIP_DIRS)$" && continue
    [ -L "$entry" ] && continue

    if [ -d "$entry/.git" ]; then
      # This is a repo — report it and check TASKS.md
      local rel="${entry#./}"
      rel="${rel%/}"
      echo "${indent}[repo] $rel"
      if [ -f "$entry/TASKS.md" ]; then
        if grep -q "## Backlog" "$entry/TASKS.md"; then
          echo "${indent}  TASKS.md: has backlog"
          if grep -q "### Ungroomed" "$entry/TASKS.md"; then
            echo "${indent}  TASKS.md: has ungroomed items"
          fi
        else
          echo "${indent}  TASKS.md: no backlog section"
        fi
      else
        echo "${indent}  no TASKS.md"
      fi
    else
      # Not a repo — check for workspace/container docs, then recurse
      local rel="${entry#./}"
      rel="${rel%/}"

      if [ -f "$entry/CLAUDE.md" ]; then
        echo ""
        echo "${indent}=== $rel/CLAUDE.md ==="
        head -100 "$entry/CLAUDE.md"
        local lines
        lines=$(wc -l < "$entry/CLAUDE.md" | tr -d ' ')
        if [ "$lines" -gt 100 ]; then
          echo "${indent}  ... (truncated, $lines total lines)"
        fi
      fi

      if [ -f "$entry/docs/architecture.md" ]; then
        echo ""
        echo "${indent}=== $rel/docs/architecture.md ==="
        head -100 "$entry/docs/architecture.md"
        local lines
        lines=$(wc -l < "$entry/docs/architecture.md" | tr -d ' ')
        if [ "$lines" -gt 100 ]; then
          echo "${indent}  ... (truncated, $lines total lines)"
        fi
      fi

      # Recurse into children
      scan_dir "$entry" "$indent  " $((depth + 1))
    fi
  done
}

echo ""
echo "=== Top-Level Documentation ==="
if [ -f "CLAUDE.md" ]; then
  echo "--- CLAUDE.md ---"
  head -100 CLAUDE.md
  lines=$(wc -l < CLAUDE.md | tr -d ' ')
  if [ "$lines" -gt 100 ]; then
    echo "  ... (truncated, $lines total lines)"
  fi
else
  echo "No CLAUDE.md found at this level."
  echo "Run /reggie-setup-workspace-docs first to generate repo responsibility mappings."
fi

if [ -f "docs/architecture.md" ]; then
  echo ""
  echo "--- docs/architecture.md ---"
  head -100 docs/architecture.md
  lines=$(wc -l < docs/architecture.md | tr -d ' ')
  if [ "$lines" -gt 100 ]; then
    echo "  ... (truncated, $lines total lines)"
  fi
fi

echo ""
echo "=== Recursive Repo & Workspace Scan ==="
scan_dir "." "" 0

echo ""
echo "=== User Input ==="
echo "The user's notes will follow this context block."
```

## Instructions

You are distributing tasks from high-level notes to individual repos. This runs at the workspace or all-projects level.

**IMPORTANT**: The user's notes are provided as the initial prompt that triggered this command. Read them carefully.

### Phase 1: INTAKE — Parse Notes

Parse the user's freeform notes into discrete task items:

1. **Split compound items**: "add API endpoint and update frontend" → two separate tasks
2. **Promote implied tasks**: "the login flow needs tests and the button is broken" → test task + bug fix task
3. **Discard non-tasks**: Remove observations, questions, or commentary that aren't actionable
4. **Normalize language**: Each task should start with an action verb (add, fix, update, implement, remove, refactor)

Present the parsed tasks:

```
Parsed [N] tasks from your notes:

1. Add API endpoint for user preferences
2. Update frontend settings page to call new endpoint
3. Fix login button not responding on mobile
4. Add tests for the login flow
5. Refactor shared utility functions into common package

Continue with distribution? (y / edit)
```

If the user says "edit", let them adjust the list conversationally.

### Phase 2: DISTRIBUTE — Match Tasks to Repos

Using the documentation gathered from all levels — CLAUDE.md files at the all-projects, container, and workspace levels, plus `docs/architecture.md` at workspace levels (all generated by `/reggie-setup-workspace-docs`) — match each task to the most appropriate repo:

1. Read the repo responsibility mappings from all available CLAUDE.md and architecture docs. Workspace-level docs have the most specific repo-to-domain mappings; use those for precise routing.
2. For each task, determine which repo owns that domain/area
3. For **cross-repo tasks**, split into per-repo sub-tasks:
   - "Add API endpoint and update frontend" → backend repo gets "Add API endpoint for X", frontend repo gets "Update settings page to call X endpoint"
4. For tasks that don't clearly map to any repo, flag them for user assignment

Present the proposed distribution:

```
Proposed distribution:

backend-api (3 tasks):
  1. Add API endpoint for user preferences
  2. Fix rate limiting on auth endpoints
  3. Add integration tests for preferences API

frontend-app (2 tasks):
  4. Update frontend settings page to call preferences endpoint
  5. Fix login button not responding on mobile

shared-utils (1 task):
  6. Refactor shared utility functions into common package

Unassigned (needs your input):
  7. Update deployment documentation — which repo owns docs?

Does this distribution look right? (y / adjust)
```

If the user says "adjust", let them reassign tasks conversationally.

### Phase 3: WRITE — Save to TASKS.md

After approval, write each task to the target repo's TASKS.md:

1. For each repo that received tasks:
   - Read the repo's existing TASKS.md (if it exists)
   - Find or create the `## Backlog` section
   - Find or create the `### Ungroomed` subsection at the bottom of Backlog
   - Append each task as `- [ ] slug: Description [P2]`
   - Generate a slug from the task description (lowercase, hyphenated, max 40 chars)

2. **TASKS.md format** for each entry:
   ```markdown
   - [ ] add-preferences-endpoint: Add API endpoint for user preferences [P2]
   ```

3. If a TASKS.md doesn't exist in the repo, create one:
   ```markdown
   # Tasks

   ## Active Tasks

   ---

   ## Backlog

   ### Ungroomed

   - [ ] slug: Description [P2]
   ```

4. **Do NOT modify any existing tasks** in the TASKS.md files. Only append to `### Ungroomed`.

### Output

After writing, present a summary:

```
Tasks distributed:

  backend-api/TASKS.md:
    + add-preferences-endpoint: Add API endpoint for user preferences
    + fix-rate-limiting: Fix rate limiting on auth endpoints
    + test-preferences-api: Add integration tests for preferences API

  frontend-app/TASKS.md:
    + update-settings-page: Update frontend settings page to call preferences endpoint
    + fix-login-button: Fix login button not responding on mobile

  shared-utils/TASKS.md:
    + refactor-shared-utils: Refactor shared utility functions into common package

Total: [N] tasks across [M] repos

Next steps:
  - Run /reggie-init-tasks in each repo to refine these into implementation-ready tasks
  - Or use the "Init Ungroomed Tasks" button in Forge to do this automatically
```

### Edge Cases

- **No CLAUDE.md found**: Warn the user and suggest running `/reggie-setup-workspace-docs` first. Offer to proceed anyway by asking the user to manually assign repos.
- **Single repo**: If only one repo exists, assign all tasks to it (no distribution needed).
- **Empty notes**: Ask the user to provide notes before proceeding.
- **Duplicate tasks**: If a task already exists in a repo's TASKS.md (matching slug), skip it and note the duplicate.
