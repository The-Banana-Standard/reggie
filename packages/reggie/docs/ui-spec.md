# Reggie Guidebook: Web UI Specification

Winning design: "Reggie Guidebook (story + map)", with the judges' grafts folded in (channel separation, ghost bands, entry markers, edge projection, state machine as data, question-first repo landing, entity links everywhere, generated legends, deterministic layouts).

Ground truth this spec was written against (live server at `http://127.0.0.1:4310/`, repo `reggie` on branch `repo-manager`, HEAD `1fb7aa2`): 262 files, 140 code files (49 of them tests or fixtures), 341 import edges, 52 `#[tauri::command]` attributes / 51 distinct command names, 63 `invoke("…")` call sites naming 48 distinct commands in 21 TS files, 8 note files with 1 stale entry (`packages/reggie/` dir note dated 2026-09-06; the folder changed 2026-09-07), 3 journal entries all on slug `repo-manager-mvp`, 0 tasks, 0 intake items, 1 person (`jacobpress`), 356 commits (352 by one author), `git log --numstat --since=365.days` = 0.08 s.

## 0. Scope and phasing

Everything not marked **⧗ STRETCH** is Core and is sized for one engineer in four working days (two engineers in two to three days using the split in the implementation order). Stretch items are fully specified so they can be picked up later without redesign, but nothing in Core depends on them.

Core: Levels 1 (Repo), 2 (Area), 3 (File) with story + map in lockstep; Level 0 (Workspace) in its minimal form; Spotlight; breadcrumb + hash router; search palette; lenses Structure / Knowledge / Tests / Heat / Owners; task board with state machine and inline capture; task page with blast radius; local POST endpoints (capture, note, decide, journal); static UI files served from `packages/reggie/ui/`; vendor-first script loading with CDN fallback; empty, loading and error states; collapsible panes and sections (the Dense toggle was retired 2026-09-14).

⧗ STRETCH: Level 4 (Symbol reference map and `calls` edges), Treemap tab, Timeline lens, People pages, Tasks lens on the container map, entry-point pin nodes and "Trace from here", cross-repo `shares-service` edges, route nodes as searchable entities, Mermaid/SVG export, TypeScript compiler-API symbol extractor, tree-sitter for Rust, sentence-bank phrasing variation.

## 1. Principles (binding on every view)

1. **Story + Map in lockstep.** Every level renders a Story column (plain English, generated server-side by `src/story.ts`) and a Map (Cytoscape). Each paragraph carries `data-refs` (graph node ids); hovering or scrolling a paragraph highlights those nodes; clicking a node pins a four-sentence Spotlight card at the top of the Story. Both routes to any entity land on the same URL.
2. **One entity model, one id scheme, one route per entity.** Every path, slug, handle, note entity, or commit rendered anywhere is an `<a href="#/…">` produced by one helper (`entityLink`). Nothing is plain text that could be a link.
3. **No hairball, ever.** The server never returns more than 40 drawable nodes for a canvas (overflow folds into `+N more` nodes). Edges between containers are aggregated to one weighted edge per ordered pair. Every layout is dagre (layered); force layouts are not used anywhere. Positions are deterministic for the same payload; filters and lenses never re-run layout.
4. **Connections are never thrown away.** When a view is scoped to a subtree, every edge that leaves the subtree is projected onto a ghost node (the nearest visible container of the other endpoint) and merged into a weighted edge.
5. **One hue channel per view, named in the legend.** Area hue (Structure), direction hue (explorer), lens fill (Knowledge, Tests, Heat), or people palette (Owners); never two at once. Status colours (`--ok --warn --bad --info`) are reserved for meaning. Selection and story highlight are achromatic (white outline + white halo) so they never overwrite a data colour.
6. **Absence is stated.** Every empty section says why it is empty and what fills it, in the story register, with the command as a secondary hint.
7. **Confidence is stated in words.** Any heuristic edge (name-matched IPC, regex `calls`) says so in its tooltip and story sentence and is drawn dotted.

## 2. Level structure

Ids: `repo:<name>`, `dir:<path>/` (always trailing slash; `dir:./` is the repo root), files keep their repo-relative path as id (`packages/reggie/src/graph.ts`), `sym:<file>::<name>`, `task:<slug>`, `person:<handle>`, `entity:<kind>:<name>`, `fold:<parent-id>:<side>` (view-only). Routes: `#/ws`, `#/repo/<name>`, `#/repo/<name>/area/<path>`, `#/repo/<name>/file/<path>`, `#/repo/<name>/symbol/<path>::<name>`, `#/repo/<name>/tasks`, `#/repo/<name>/task/<slug>`, `#/repo/<name>/people` ⧗, `#/repo/<name>/person/<handle>` ⧗, `#/repo/<name>/time` ⧗. Query string after the hash path: `?lens=structure|knowledge|tests|heat|owners|tasks&depth=1|2|3&dir=both|up|down&tests=1&tab=map|treemap`. In single-repo mode `#/` redirects to `#/repo/<facts.name>`; in workspace mode `#/` redirects to `#/ws`.

### Level 0: Workspace (`#/ws`)

*When*: the server was started with `--workspace <dir>` or auto-detected one (see §6.7). Single-repo mode skips this level; the breadcrumb still shows a greyed "Workspace" crumb with tooltip "Start `reggie serve --workspace <dir>` to see sibling repos".

*Story*: title = workspace name (H1 of the workspace CLAUDE.md). Sections: **Needs you** (awaiting-decision tasks across repos: `[[task]] in [[repo]], owner, age`; hidden when empty), **Repos** (one paragraph per repo: "`[[reggie]]` is <description>. <primary language>, <N> code files. <task counts in words>. <coverage>% of its source files have a note. Last recorded: '<last journal text, first sentence>' (<person>, <date>)."), **How they connect** (one sentence per edge: "`forge-reggie` and `reggie` share the GitHub org The-Banana-Standard" / "`color-lock-web-app` depends on `color-lock` (package `@color-lock/shared`)"; empty text: "No dependency between these repos was found in their manifests.").

*Map*: one node per repo, rounded rectangle 200×72, label line 1 = repo name (15px/600), line 2 = "<language> · <N> code files" (12px muted). Fill `--panel-2`, border `--line-strong`. Layout dagre `rankdir: LR` when any edge exists, otherwise a single row spaced 48px. Edges: `depends-on` solid 1.5px with the package name as label; `same-org` dashed muted, no label, drawn only if no stronger edge exists between the pair. Below the map: an HTML tile strip, one tile per repo, showing the five task-state counts as a 6px stacked bar in the state colours (§5.1) plus digits, and a coverage bar (noted green, inherited light green, undocumented grey, stale red notch). Tiles and nodes cross-highlight on hover.

*Drill-down*: click node, tile, or repo name → `#/repo/<name>`. Click a task in Needs you → task page.

*Map (container map)*: one node per L1 area from `chooseAreas` (§6.2). On this repo that yields exactly 7 nodes: `packages/reggie`, `src-tauri`, `src/components`, `src/hooks`, `src/types`, `src/services`, `src (other)`. Fill = area hue (§5.1) at 100%; text `--text`. Edges: one per ordered pair of areas; `width = 1.5 + 6 * log(weight) / log(maxWeight)`; label = weight when ≥ 2; straight lines, `arrow-scale 1.2`, colour `#4b5568`. Click an edge → Spotlight listing the top 5 file pairs behind it (`via`), each a link to the file level. Click an entry name → file explorer preset downstream. Click a task → task page.

### Level 2: Area (`#/repo/<name>/area/<path>`)

*Story sections*: **Read these first** (the note chain: repo note, each ancestor folder note, this folder's note; verbatim with chips; stale entries get a red "Possibly out of date" chip with "written <date>, code changed <date>"), **What is in here** (children ranked by fan-in: "[[paths.ts]] is the most relied-on file here: 19 other files use it." then sub-areas: "[[ActivityBar]] holds 8 components."), **What it depends on** / **What depends on it** (grouped by ghost: "Uses [[src/types]] for 3 files (41 imports)"), **Tests** ("14 test files cover 12 of 21 source files. Untested: [[serve.ts]], [[mcp.ts]] …" amber), **Who works here** ("[[jacobpress]] wrote 98% of the lines changed in the last year. One person holds this area." when busFactor = 1), **Tasks that will touch this area** (plans naming files here, with state), **Recently** (journal entries whose evidence or slug maps here; last 5 commits: "jacobpress changed 3 files here on 7 Sep: <subject>"), **Add a note** (inline form: type select, confidence select, textarea, submit → POST `/api/note`, writing to this folder — always present, unlike the form on **Read these first**, which goes as soon as the chain has anything in it, including a note inherited from the repo).

*Map (focus-plus-context)*: a compound node (soft rounded rectangle, fill area hue at 12%, border area hue, label = area path at top-left 12px) containing the area's **children as chosen by `chooseAreas(root)`**: a child directory with ≥ 3 source files is a collapsed sub-area node (same style as L1 nodes, smaller: 96×44); every other source file is a circle sized by fan-in (16–40px, sqrt). Around the compound: **ghost nodes** for every outside container that exchanges at least one edge with the children (§6.3 for the ghost rule), drawn 96×40 rounded rectangles with dashed border, fill area hue at 35%, label "src/types · 3 files used". Ghosts are included in the dagre run so dagre places upstream ghosts above the compound and downstream ghosts below; a ghost with edges in both directions is emitted twice (`ghost:up:` and `ghost:down:` prefixed ids) so bands stay clean. Layout dagre TB, `rankSep 70, nodeSep 28`. Edges inside: file-to-file import edges, bezier 1.5px, arrow-scale 1.2. Child→ghost edges: one per pair, width by weight, label weight when ≥ 2. Test files: hidden by default; the toolbar shows "Show tests (14)"; when on, tests are hollow circles with a dashed border and `tests` edges are dotted grey. More than 40 children: the lowest fan-in files fold into one `+N more` node (grey, dashed) that expands on click (route gains `?all=1`).

*Interactions*: click a file node or file name → `#/repo/<name>/file/<path>`; click a sub-area → descend (route). Click a ghost → navigate to that area; the map animates: the old compound shrinks into a ghost and the new one expands (350 ms, `cy.animate` from previous positions). Hover a file node: importers light cyan, imports light orange for the duration (a temporary direction highlight; the legend does not change), and the map footer reads "Used by 6 · Uses 9". Toolbar: Fit, Zoom −/+, Re-layout, Show tests, Lens.

### Level 3: File (`#/repo/<name>/file/<path>`)

*Story*: Spotlight is pinned automatically (from `/api/explain`), then **Read these first** (note chain with stale chips), **What it exports** (symbol outline: `[[name]]` kind, line, "used by N files"; rows link to Level 4 ⧗, in Core they scroll the reader to the declaration), **Who uses it** (importers grouped by area, tests separated: "used by 2 files in [[packages/reggie/src]] and 1 test"), **What it uses** (imports grouped by area; external packages listed as plain chips "commander, yaml"), **Tests** ("[[graph.test.ts]] imports this file." or amber "No test imports this file."), **Tasks** (touching plans with state), **History** (last 8 commits: author, date, subject; "Changed 3 times in 30 days, all by jacobpress."), **Add a note** (inline form: type select, confidence select, textarea, submit → POST `/api/note`). Button **Read the source** opens the reader: a drawer under the map, or the whole column when the map pane is folded.

*Map (explorer)*: the file at the centre rank; importers (upstream) in ranks above, imports (downstream) in ranks below; dagre TB, `rankSep 64, nodeSep 24`. Area hue is OFF: nodes are circles with neutral fill `#2a3140`, border 2px `--up` cyan for upstream, `--down` orange for downstream, white for the centre (24px). Labels always on (12px). Edge colour follows the side. Controls: depth 1–3 (default 1), direction Both / What depends on me / What I depend on, Show tests, counts "12 upstream · 9 downstream at depth 2", Back (in-page history stack), Fit. More than 40 nodes on a side: fold by area into `+N more in src/components` nodes that expand on click. Edge tooltip: "serve.ts imports buildGraph, RepoGraph from graph.ts" from the named-import list. Cycles through the centre are called out in the story and the return edge is `--bad`.

*Reader drawer*: under the map, 40% of the map column height by default, resizable by dragging its top edge (min 120px), slides 200 ms. Line-numbered source from `/api/file` (first 20 000 chars; a banner "Showing the first 20 000 of N characters" when truncated), monospace 12px, exported symbols marked in the gutter with a ▸ glyph; clicking a gutter mark or an outline row scrolls that line into view and highlights the span `line..endLine` with `--panel-2`. Selecting text shows a floating "Add a note about lines a–b" button that prefills the note form's text with `(lines a–b)`. "Open in editor" link = `vscode://file/<abs path>:<line>` (scheme overridable by `config.yaml` `editorScheme`).

*Drill-down*: click a neighbour node or name → explorer re-centres (route push, positions animate 350 ms). Click an area name → Level 2. Click a symbol → Level 4 ⧗ (Core: reader scroll). Escape → clear highlight, then pop history, then close Spotlight.

### Level 4: Symbol (`#/repo/<name>/symbol/<path>::<name>`) ⧗ STRETCH

Story: "`buildGraph` is an exported function defined at line 168 of [[graph.ts]]. It is used by 2 files: [[serve.ts]] and [[cli.ts]] (exact, from named imports). Inside, it calls listRepoFiles, isIgnoredPath and 9 helpers in the same file (matched by name; may include false matches). No note mentions it by name." Then **What breaks if I change it** (upstream files to depth 2). Reader opens at the declaration. This is the floor: every node links back up.

## 3. Views and panels

### 3.1 Guidebook shell

Header 48px; below it a flex row of panes: the Story (min 380px, capped at its 62ch measure plus padding, so spare width goes to the map) and the Map column, which on file pages also holds the code reader. Each pane folds: Story / Map / Code toggles in the header (`S`, `M`, `C`), and a 28px rail stands where a folded pane was and reopens it. One pane alone fills the row (a story alone sits centred); story beside map, story beside code (the reader at full height) and map beside code (side by side) are the pairs; all three are story beside map over code, with the drawer's drag handle. Choices are remembered per level (`reggie.panes.<level>`). Every story section folds from its heading (`[` / `]` fold or open them all; remembered per repo and level under `reggie.sections.<repo>.<level>`). Under 1100px the panes stack, map first at 45vh, sticky mini-breadcrumb, no toggles or rails. The Story column scrolls; the Map is `position: sticky; top: 48px; height: calc(100vh - 48px)`. Header: breadcrumb left (crumbs from `story.crumbs`, each a link; the last crumb is the page title at 22px/600), right: search trigger ("Search ⌘K"), Lens segmented control, the Story / Map / Code pane toggles, repo switcher (workspace mode only). Map column contains: tabs row (Map / Treemap ⧗) 32px, canvas, toolbar (top-left floating card: Fit, −, +, Re-layout, Show tests, Depth/Direction when applicable), legend (bottom-left floating card), footer line (bottom-right: counts like "7 areas · 12 edges · 49 tests hidden"; on the repo map a last segment "· 2 imports point at no file" is appended when `counts.unresolved` is positive and omitted entirely when it is zero, and it appears on no other level because the number is repo-wide), reader drawer (Levels 3–4). Spotlight slot sits above the story sections.

Dense toggle: retired 2026-09-14. Folding sections and panes replaces it; `?dense=1` in an old link is ignored.

Router: `hashchange` → parse route → `render(route)`: fetch (with an in-memory cache keyed by URL, 10 s TTL) `/api/story`, the level's graph endpoint, and `/api/facts` once; render story then map. `pushState` for navigation, `replaceState` for query-only changes (lens, depth, tests). Browser Back/Forward restores everything from the hash.

Keyboard: `⌘/Ctrl+K` search; `F` fit; `T` toggle tests; `S` / `M` / `C` fold or open the story, map and code panes; `[` / `]` fold or open every section; `1–5` lenses; `Escape` unwinds (highlights → focus history → Spotlight → palette); `Backspace` (when focus is not in an input) goes up one crumb; `Tab` walks story links (focus ring 2px `--info`); arrows in board and palette.

Loading: story column shows the level's section headings immediately with three-line skeleton bars under each; the map keeps the previous level's nodes at opacity 0.35 until the new payload arrives (first load: an empty canvas with a centred card "Reading the repo: files ✓ imports ✓ notes … git history …" driven by `/api/status` ticks). Error: an inline card in the story ("`/api/story` failed: <message>" + Retry) and the map keeps whatever it had. Renderer failure: the map column shows "The map library did not load. The story still works. Expected `/vendor/cytoscape.min.js` (from packages/reggie/node_modules) or cdnjs." and every map-only control is disabled; the story, board, palette and reader keep working.

### 3.2 Story column (`ui/story.js`)

Renders `Story` payload: sections in order; each section: `h2` (17px/600), 1px `--line` rule, paragraphs 12px apart. Paragraph text uses `[[route|label]]` link markup rendered through `entityLink` (kind glyph + label). Paragraph kinds: `fact` (plain), `note` (card, left border by note type colour, chips row), `journal` (card, chips Person / Tool / Stage / Task), `gap` (left border `--warn`), `commit` (mono sha chip + subject), `decision` (card with Approve / Needs work buttons), `list` (bulleted). Each paragraph element gets `data-refs`. `mouseenter` → `map.highlight(refs)`; `mouseleave` → `map.clearHighlight()`. An `IntersectionObserver` (rootMargin `-30% 0px -60% 0px`) marks the paragraph crossing the top third as `.reading` and calls `map.softHighlight(refs)` (halo 0.12, no dimming). Refs that are not on the canvas resolve client-side to the nearest visible ancestor or ghost (`map.resolveRef`) and the tooltip says "inside packages/reggie (folded)".

Map→story: `map.on('hover', id)` tints the left border of every paragraph whose refs include `id` (`--info` at 60%); `map.on('tap', id)` fetches `/api/explain?id=` and pins the Spotlight; `map.on('dbltap', id)` navigates to the node's route.

### 3.3 Spotlight card

Pinned at the top of the story column: kind glyph + title (17px/600) + kind badge + area crumbs (12px links); exactly four sentences (what it is; who talks to it; who knows about it; what is happening to it), each with links and `data-refs`; three actions: **Go deeper** (route), **Show what breaks if it changes** (explorer `?dir=up&depth=2`), **Add a note** (scrolls to / opens the note form). Close with × or Escape. Only one pinned at a time; pinning animates 180 ms fade.

### 3.4 Map (`ui/map.js`) contract

One Cytoscape instance created once the container has a non-zero size (`ResizeObserver`); `minZoom 0.1, maxZoom 4`, default wheel sensitivity, `boxSelectionEnabled false`. Public API: `show(view: ViewGraph, opts: {lens, level})` (diffs elements by id: removes gone, adds new, updates data, runs dagre with `animate: true, animationDuration: 350` only when the node set changed; `fit(…, 30)` 250 ms after), `setLens(lens)`, `highlight(ids)`, `softHighlight(ids)`, `clearHighlight()`, `select(id)`, `resolveRef(id)`, `fit()`, `relayout()`, `on(event, fn)`. Positions per `level+root` are cached in localStorage (`reggie.pos.<repo>.<level>.<root>`) and used as `preset` for nodes still present; new nodes are placed by dagre; Re-layout clears the cache entry and re-runs dagre. Window resize → `cy.resize()` and `fit` if the viewport no longer intersects the element bounding box. Tooltips: a single absolutely positioned `div.tip` moved on `mouseover` (no popper): nodes show full path + role + lines + note state + commits30; edges show the sentence from `names`/`via`.

## 6. Data model (server, `packages/reggie/src`)

### 6.1 `graph.ts` (extended, stays the single extractor)

`buildGraph(paths, opts?)` returns `RepoGraph` (see contract) containing **every** node kind below; views (§6.3) project it. Additions:

- **Roles** (`roles.ts`, new, shared with `facts.ts`): `roleOf(path)`: `test` when `TEST_HINTS` match or path contains `/__tests__/`; `fixture` for `/__test-utils__/`, `/__mocks__/`, `/fixtures/`, `test/helpers.*`; `config` for `*.config.*`, `tsconfig*.json`, `build.rs`, `vite-env.d.ts`, `*.d.ts`; `generated` for `dist/`, `*.gen.*`, first line containing `@generated` or `DO NOT EDIT`; else `source`. Edges whose source has role `test` or `fixture` are emitted with `kind: 'tests'`. Per source file `testedBy = [test files importing it]`.
- **Named imports**: `jsImports` returns `{spec, names: string[], isType: boolean}` (names from `import { a, b as c }`; default import as `default`, namespace as `*`). Edges carry `names`. Rust `use crate::a::{b, c}` and `use reggie_lib::x` likewise.
- **Hierarchy**: a `dir` node for every directory on the path of every code file (full depth), `parent` links, `dir:./` for the repo root, `repo:<name>` above it. Each dir carries `aggregates` (files, source, tests, config, lines, documented, testedSource, tasks) computed in one post-order pass; `manifest` = `package.json` | `Cargo.toml` | null when that file sits in the directory (root `package.json` counts for `dir:./`); `label` = manifest name when present (`reggie_lib` for the Cargo `[lib]`), else the directory basename.
- **Knowledge join**: per node `knowledge = {own, inherited, stale, byType, lastNoteDate, lowestConfidence}` from `allNoteFiles` (read once) and the batched staleness map (§6.4); `inherited` = number of ancestor dir/repo entries. Entity notes (`_entities/*`) become `entity:<kind>:<name>` nodes; each entry's `sources` create `annotates` edges from the entity node to the cited file/dir node.
- **Boundary edges**: (a) Tauri IPC: regex `/#\[tauri::command\]\s*(?:pub(?:\([^)]*\))?\s+)?(?:async\s+)?fn\s+(\w+)/g` over `.rs` builds `name → file`; regex `/invoke(?:<[^>]*>)?\(\s*['"]([a-z_][a-z0-9_]*)['"]/g` over `.ts/.tsx` emits `ipc` edges file→defining file with `names` = command names and `confidence: 'exact'` (matched by name, stated as such in tooltips); (b) Rust lib crate: `rustEdges` additionally resolves `use <name>::` and `<name>::path(` where `<name>` is the Cargo `[lib] name` or the `[package] name` with `-`→`_`, to `<crate>/src/lib.rs`, so `src-tauri/src/main.rs → src-tauri/src/lib.rs` exists; (c) entry markers: file nodes get `entry: true` and `entryKinds` from `facts.entryPoints` plus detectors: commander `.command("x")` count → `{kind:'cli', count}`, `registerTool("x")` → `mcp`, `case "/api/x"` → `http`, files defining ≥ 1 `#[tauri::command]` → `ipc-server`. Detectors live in `BOUNDARY_DETECTORS: Detector[]` (`{id, filePattern, regex, kind}`) so `config.yaml` `boundaries: [{id, file, regex, kind}]` can add or replace them ⧗ (Core ships the list; the config hook is a 10-line read).
- **Tasks**: task nodes for every task from `listTasks(paths, config, {includeDone: true})` (intake items included as ungroomed), with `state, risk, owner, age`. `touches` edges from the union of plan files (disk, else `fileAtRef(base)`), `changedFiles` on `task/<slug>` (vs base), and packet Changes; a folder entry targets the `dir:` node, never a child. Per file `tasks: string[]`.
- **Symbols**: `symbols` (§6.5) are computed lazily per file and cached by content hash; not part of `RepoGraph` payloads except `/api/file` and `/api/symbols`.
- **History**: per file `history` from §6.4 attached when available; dir roll-ups in `aggregates.history`.
- **Cycles**: `tarjan(nodes, edges)` helper in `views.ts`; file-level SCCs of size ≥ 2 stored as `graph.cycles`.
- **Compatibility**: `dir`, `dirKey`, `noteCount`, `dirNoteCount`, `inDegree`, `outDegree`, `unresolved`, `dirs`, `languages` are kept so the existing test and any consumer of `GET /api/graph` (no params) still work; `MAX_NODES` remains only for the flat compatibility payload and the response now carries `totalCodeFiles, included, truncated`.

### 6.2 Adaptive area selection (`views.ts: chooseAreas(graph, rootId, {maxNodes: 40, minFiles: 3})`)

Counts use **source files only** (roles `source`). Returns `{areas: NodeRef[], loose: fileIds[]}` for a root:
1. Candidate children = subdirectories of root. Any child directory holding a manifest is promoted first.
2. Any candidate with `source > maxNodes` is split one level deeper if the split yields ≥ 2 grandchildren with ≥ `minFiles`; the residual (grandchildren under `minFiles` plus the candidate's own files) stays as the candidate itself flagged `residual: true`, labelled "<name> (other)", with aggregates recomputed for the residual set.
3. Candidates with fewer than `minFiles` source files are folded: their files join the parent's `loose` set.
4. `config.yaml` `areas: [paths]` pins the result for `dir:./` (each listed path becomes an area; unlisted code folds into `(other)`).
5. Level 1 = `chooseAreas(dir:./)`; Level 2 for `R` = `chooseAreas(R)` (sub-areas) plus `loose` files; if `sub-areas + loose > maxNodes`, the lowest fan-in loose files fold into one `fold:` node.

On this repo, Level 1 yields `packages/reggie` (manifest; 21 source / 32 files), `src-tauri` (manifest; 18/19), `src/components` (29/54), `src/hooks` (5/10), `src/types` (7/8), `src/services` (3/6), `src (other)` (5 source: `App.tsx`, `main.tsx`, `lib/*`, `data/*`, plus tests/config). Root files (`vite.config.ts`, role config) do not create a node.

### 6.3 Views (`views.ts`, pure functions over `RepoGraph`)

- `containerView(g)`: L1 areas + aggregated edges. Aggregation: for each file edge (not `tests`), map both endpoints to their L1 area; if different, increment `(a, b, kind)`; `via` keeps the top 5 `{source, target, names}` pairs by names length. IPC edges aggregate separately (`kind: 'ipc'`, label "IPC · N" where N = distinct command names). Cycles: Tarjan over the aggregated graph. `areas` list with hue index by source count.
- `dirView(g, root, {tests})`: children per §6.2; intra edges; ghosts: for a neighbour file `f` outside `root`, ghost = the L1 area containing `f` when it differs from the L1 area containing `root`; otherwise the child of `root.parent` (per `chooseAreas(root.parent)`) that contains `f`, or `root.parent` itself (residual) when `f` is loose there. Emit `ghost:up:<id>` when the ghost only imports from children, `ghost:down:<id>` when it is only imported, both when both. Child→ghost edges aggregated with `weight`, `via`, `names` union (top 8).
- `impactView(g, id, {depth, direction, tests})`: BFS over `import|mod|ipc` (plus `tests` when enabled) predecessors (up) and successors (down) to `depth`; nodes carry `side` and `hop`; per side per hop, if a hop exceeds 40 nodes, group the overflow by L1 area into `fold:` nodes (`foldCount`, `foldIds`). Counts per hop returned. Multiple ids (task blast radius) share one BFS with `centers`.
- `treemapTree(g, root)` ⧗.

### 6.4 `history.ts` (new)

`repoHistory(root): HistoryIndex` runs once per HEAD sha: `git log --numstat --format=%H|%an|%ae|%aI|%s|%(trailers:key=Task,valueonly,separator=;) --since=365.days HEAD`, parses into per-path `{commits30, commits90, commits365, linesChanged, lastTouched, authors: Map<email,{name, lines, commits}>}` plus `commitsByPath` (last 8 `CommitInfo` per path, with `task` slug from the trailer or a `task/<slug>` merge subject) and `commitsPerDay`. Renames (`R100 a => b`) attribute to the new path. `busFactor` = number of authors with ≥ 20% line share (min 1). Roll-up per directory in the same post-order pass as aggregates. Cached in memory keyed by HEAD sha and on disk at `.reggie/.cache/history-<sha>.json` (add `.reggie/.cache/` to the repo `.gitignore` during onboard; derivable data). `lastTouched` per path also feeds `staleEntriesFor(paths, notes, lastTouchedMap)` (new optional third parameter in `notes.ts`) so staleness costs one git call, not one per note. Authors are joined to `people.yaml` by email → `handle`; unknown emails get `handleFor(name, email)`.

### 6.5 `symbols.ts` (new; regex now, compiler API ⧗)

`extractSymbols(file, content): Symbol[]` with `{name, kind, line, endLine, exported}`. TS/JS: `^\s*export\s+(?:default\s+)?(?:declare\s+)?(?:async\s+)?(function\*?|class|const|let|var|type|interface|enum)\s+([A-Za-z_$][\w$]*)`, `^\s*export\s+default\s+(?:function\s*)?([A-Za-z_$][\w$]*)?`, `^\s*export\s*\{([^}]+)\}` (each `a as b` → `b`, marked `reexport`), `module\.exports\.(\w+)`; non-exported top-level `function|class` declarations are included with `exported: false`. Rust: `^\s*(pub(?:\([^)]*\))?\s+)?(?:async\s+)?(fn|struct|enum|trait|type|mod|const|static)\s+([A-Za-z_]\w*)` with `exported = pub present`, plus `tauriCommand: true` when preceded by `#[tauri::command]`. `endLine`: brace counting from the declaration line (strings and comments stripped by a simple state machine); fall back to next top-level declaration − 1. `usedBy(graph, file, name)`: importers whose edge `names` include `name` (exact). `calls` ⧗: identifiers followed by `(` inside the span, resolved to same-file declarations or named imports, `confidence: 'heuristic'`, with a stoplist (`new, run, get, set, map, filter, then, catch, log`). Cache: `Map<file, {hash, symbols}>` keyed by content sha1.

### 6.6 `story.ts` (new; pure, DOM-free, unit tested; also the narration source for the podcast composer)

`repoStory(ctx)`, `areaStory(ctx, id)`, `fileStory(ctx, id)`, `taskStory(ctx, slug)`, `workspaceStory(ws)`, `symbolStory` ⧗, `personStory` ⧗, `timeStory` ⧗, and `explain(ctx, id)`. `ctx = {facts, graph, views, tasks, journal, notes, people, history, stateMachine}` assembled by `serve.ts`. Sentences never contain raw paths without link markup.

POST handling: only when `req.socket.remoteAddress` is loopback, `Sec-Fetch-Site` is `same-origin` or `none`, and `Origin` (if present) matches the server's own origin; body ≤ 64 KB JSON; writes only through `capture`, `addNote`, `decidePacket`, `appendJournal` (person = `currentPerson`, tool `human`, journal text "via web"). `/api/status` returns build progress flags for the first-load card.

## 7. Libraries (all pinned; vendor-first, CDN fallback)

- **cytoscape 3.30.4** (`https://cdnjs.cloudflare.com/ajax/libs/cytoscape/3.30.4/cytoscape.min.js`) — the one graph library. Justification: it is the only CDN-loadable engine with compound (parent) nodes, a selector-based stylesheet, per-element classes for instant lens swaps in `cy.batch`, animation from preset positions, and a headless mode in node for the later SVG/Mermaid export; measured 2–7 ms frames at 140 nodes and our cap is 40. Sigma/WebGL would only pay off above thousands of raw nodes, which the aggregation contract forbids; d3-force adds nothing because force layouts are banned.
- **dagre 0.8.5** (`https://cdnjs.cloudflare.com/ajax/libs/dagre/0.8.5/dagre.min.js`) + **cytoscape-dagre 2.5.0** (`https://cdn.jsdelivr.net/npm/cytoscape-dagre@2.5.0/cytoscape-dagre.js`; not on cdnjs) — every layered layout. Load order: cytoscape, dagre, cytoscape-dagre, then `cytoscape.use(cytoscapeDagre)` in `map.js`. No fcose/cose-base.
- **d3 7.9.0** (`https://cdnjs.cloudflare.com/ajax/libs/d3/7.9.0/d3.min.js`) — Treemap ⧗ and the timeline bars ⧗ only; not loaded in Core (`index.html` keeps the tag commented with the pinned URL).
- Client: vanilla ES modules, no framework, no bundler, no webfonts. Server: no new native dependencies; add `cytoscape`, `dagre`, `cytoscape-dagre` (and `d3` ⧗) as exact-version `dependencies` so `/vendor` works offline; add `"ui"` to `package.json` `files`.
- Script tags: `<script src="/vendor/cytoscape.min.js" onerror="this.onerror=null;this.src='https://cdnjs…'"></script>`; `app.js` checks `window.cytoscape && window.dagre && window.cytoscapeDagre` after `DOMContentLoaded` and renders the renderer-failure card if missing, naming the expected vendor path.

## 8. Security

Server binds `127.0.0.1` by default; POST routes refuse non-loopback sockets, cross-site `Sec-Fetch-Site`, mismatched `Origin`, and bodies over 64 KB; slugs pass `isSafeSlug`; note entities pass `resolveNoteTarget` (which already refuses escapes); `/api/file`, `/api/evidence`, `/ui/`, `/vendor/` reject `..`, absolute paths, and anything outside their base directory; the server never writes source files.
